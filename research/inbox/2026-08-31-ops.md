## 3. How a round runs

1. Scout (parent) pulls Latest from the **follow list** + one gap query (names not on the map).
2. Kick `/rh-field-round` (or spawn the four children). They do not wait on each other.
3. Auditor kills bad CAs / chain collisions before they hit the map.
4. Desk updates `listen` / `follow` / flags.
5. Compiler appends one fill, patches yaml, **one** commit, push research only.
6. Do not recap. Next scout query starts in the same turn.

## 4. Account scoring (source quality)

Axes — keep them separate. Do not collapse into one “good person” number.

| Field | Values | Use |
|---|---|---|
| `role` | project · builder · alpha · kol · data · infra · media · farm | how to read the account |
| `follow` | true / false | should we actually follow |
| `listen` | high · medium · low · mute-trend · skip-ingest | how hard we listen |
| `signal` | 0–5 | names machines, CAs, collisions |
| `reach` | 0–5 | distribution |
| `trust` | 0–5 | believe a number without checking (default 1) |
| `engagement` | organic · mixed · farm · bot | reply/like pattern |
| `conflict` | none · bag · team · paid · unknown | why they might pump |
| `flags` | impersonator · drainer · wrong-chain · self-trend · copypasta · ca-collision | operational |

**Trending** (when the site grows a feed): count only `role in [alpha, kol]` AND `listen: high`. Never `project`. Never `skip-ingest`.

**Good source (high listen)**  
Cites a handle + CA, names the *machine* (hook pad vs LP vs options vs CDP), does not mix chains, later matches Llama/Blockscout, flags collisions.

**Bad source (low / mute-trend / skip-ingest)**  
“Send it” lists, copypasta, claim-portal links (`cryptolot.lol`), wrong-chain tickers as RH, impersonators, engagement bait, paid CT with no disclosure, project accounts used as if they were CT.

Builders (`conflict: team`) can still be `follow: true` and `listen: high` for **mechanism**. Their TVL/mcap claims stay unverified.

Ledger: `research/inbox/account-desk.yaml`. Human can override any row.
