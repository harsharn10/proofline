# Research seed

Use `docs/operating-flow.md` for owners, planning time budgets and state meanings. A collected seed is
not compiled/live or independently reviewed; report the exact stage reached, never flip approval flags.

Read current GitHub main: `AGENTS.md`, `docs/ingestion.md`, `docs/research-system.md` sections 4–7 and 10,
and `docs/templates/research-packet-v2.md`. These paths are relative to the repository root.

Require a bounded assignment with main SHA, owner, slugs, allowed paths and stop condition. Before reading
expensive sources, match official domain, handle, chain/address and token ownership against census,
canonical deployments and pending producer PRs including drafts. A match is an update or controller hold,
not another token profile. Discovery inventories are leads, not accepted projects.

Collect the shared seed minimums; reproduce chain claims and keep unknowns explicit with searched surfaces.
Write one packet per assigned canonical slug, `packet_tier: seed`; use the full template shape but only
the seed-required narrative. Distinguish observation dates from collection time. Never invent evidence
or change scores to make the seed pass. Do not write `content/**`.

Validate using the repository's packet gates. Deliver one short-lived batch PR only if there is new evidence;
record assignment/task IDs and source limitations. Leave the producer PR unmerged for compilation.
Stop after the assigned batch. No automatic next round, scheduler changes, paid calls or publication.
