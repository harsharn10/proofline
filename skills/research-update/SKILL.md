# Research update and targeted backfill

Use `docs/operating-flow.md` for owners, suggested time budgets and completion stages. A full backfill
adds research depth, not editorial approval. Keep unchanged facts' observation dates and report no-change
checks without a packet; never bump dates or flags solely because a bot ran.

Read current main `AGENTS.md`, `docs/ingestion.md`, `docs/daily-registry.md`, and the applicable packet
template under `docs/templates/`. Read the assigned prior packet, canonical profile, sources and feed.

Require explicit task IDs/owner and a current pending-PR check. Already claimed, blocked, no-change,
pending or identity-held names are not new work. Use shared eligibility; don't build another relevance list.
For a material delta use `research-update-v2.md` with a supported reason, old/new difference, exact sources
and dates. Existing profile fields remain unchanged unless the evidence specifically supports changing them.

For a backfill, use `packet_tier: full` and the complete packet template. Concentrate new reads on assigned
gaps; reuse valid evidence with its original date and attribution. Record the stable task ID in Operations
log. Do not present historical events as new news; normally set their placement to `none`. Unknown/P0/P1
questions stay explicit, not cosmetically relabelled as resolved. Access denied is blocked work, not proof
of no deployment/audit. Do not retry the same blocked task without release or new accessible evidence.

Public event copy follows the website table in `docs/ingestion.md`. Compare the source event against the
existing feed, including X/Twitter URL variants. No material difference means a no-change issue note,
no packet and no PR. One material event is enough; never fill an event quota.

Only assigned packet paths may be written. Deliver a finite submission PR and stop. Independent verification,
canonical compilation, scoring decisions and publication are not the collector's jobs.
